# Contributing to Awesome Maru

Thanks for helping people discover useful work made with the Maru Engine.
This repository is at the placeholder stage. Its categories and review process
will evolve as the first resources are added.

## Suggest a resource or project

Open a pull request that adds a Markdown entry to the appropriate README
category. Keep the description short and factual. An issue is also welcome
when you want to suggest a resource or discuss where it belongs.

Include the following information in your pull request:

- Project or resource name and a short explanation of what it does.
- Author or maintainer credit and a link to the original project.
- Public source URL and an explicit licence for a community code project.
- Setup instructions, including the required Engine or SDK version.
- Supported hosts or targets, known limitations and any verification evidence.
- A demo or screenshot, if available.

Suggested entry format:

```markdown
- [Project name](https://github.com/author/project) — Short description.
  By [Author](https://github.com/author). Licence: SPDX identifier.
  Setup, requirements and limitations: link to the project's README.
```

Use real URLs and licence identifiers when submitting an entry.

## Source, licences and assets

Community code projects must provide their complete project source under an
explicit open-source licence. A public repository or a free binary alone does
not meet this requirement. Link to the project's licence file; do not describe
restrictively licensed, source-available code as fully open source.

Document dependencies and their separate terms, including the Engine's terms.
If a project includes samples, impulse responses, model weights or other
assets, identify their provenance and redistribution terms. Make any assets
that cannot be redistributed and any required external downloads clear in the
project's setup instructions.

Educational links need an identified author and an accessible original source.
Link to third-party resources rather than copying their content here. Submit
only material you have permission to contribute, and preserve attribution.
A directory listing does not change a project's licence or transfer ownership.

## Keep projects with their authors

Keep plugin source, releases, issue tracking and large assets in the project's
own repository. This repository owns the directory and small shared guides.
Do not add plugin binaries, sample libraries, vendored projects, secrets or
personal information.

## Review and maintenance

Maintainers review entries for relevance, useful documentation, attribution,
source availability and clear licensing. A listing does not establish audio
quality, host compatibility, security review or Maru release qualification.
Describe only targets supported by the project's own evidence.

To fix a broken link, update a description or remove an unavailable resource,
open a pull request. For attribution or rights concerns, open an issue with the
relevant URL and a concise explanation; avoid posting private information.
Keep discussions respectful and focused on helping creators and musicians.
